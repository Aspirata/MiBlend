# 📌 Release Plan
The current plan for upcoming releases and ongoing progress is available in [**GitHub projects**](https://github.com/Aspirata/Mcblend/projects).
If you're interested in changes planned for more distant versions, take a look at the [**milestones**](https://github.com/Aspirata/Mcblend/milestones).

Major MiBlend updates are released **every 2-4 months**, while minor patches and refinements are released as needed.

## 🔬 Experimental Builds
All commits from MiBlend's experimental branch are automatically [**published on GitHub**](https://github.com/Aspirata/MiBlend/actions) as ready-to-use addons.

**Important:** These versions may contain **critical bugs** and potentially cause serious damage to your project. They are recommended for **testing and research purposes only**.
You can learn how to install experimental builds in [this guide](en/genius-zone/how-to-install-e-branch).

The addon's information always includes a warning about its experimental status and the exact build date.

## 🚀 Milestones
When most of the tasks for a new major version are complete, a **Milestone** is released. This is a more stable version of an experimental build. While bugs and imperfections are still possible, they are **significantly fewer** than in daily experimental builds.

Single-digit milestones might be released multiple times with appended letters, for example: **Milestone 3A (M3A), Milestone 3B (M3B)**, etc. Such intermediate updates typically include nothing substantial beyond bug fixes and minor refinements.

# 🔢 Version Numbering and Naming
## 📛 How Version Names are Formed
The name for major updates is chosen based on their **main theme or key functionality**. Minor updates inherit the major version's name, and their own specific names are usually chosen more freely.

## 📌 Numbering System
MiBlend versions are numbered according to the standard **`x.y.z`** scheme, where:
* `x` — the **global update** number (e.g., the first official addon release).
* `y` — the **major update** number with new features.
* `z` — the **minor update** number, including bug fixes or small additions.

## 🔠 Version Indices
Additionally, letter indices may be present in the version name to indicate the type of changes made:
* **F** (Fix) — **Bug fixes**, without new functional additions.
* **Plus (+)** — **Small additions** to existing features.
* **S** — **Minor changes**, bug fixes, and small refinements.

# 🔄 Compatibility
## 🛠 Supported Blender Versions
MiBlend **works with all Blender versions**, starting from the oldest **updatable LTS** (currently Blender 3.6 LTS).
However, some functions and assets may be absent in older versions due to Blender's own limitations.

### Supported Versions:
* **3.6 LTS** 🟡
* **4.0** 🟡
* **4.1** 🟡
* **4.2 LTS** 🟢
* **4.3** 🟢
* **4.4** 🟢
* **4.5** 🟢

ℹ️ **Legend:** 🟢 — **Full support**, 🟡 — **Supported, but with limitations**.

## 🌍 World Exporter Support
I aim to support all Minecraft world exporters.
**jmc2obj** demonstrates the best compatibility, as it minimally alters textures and their names, and also provides more information, which contributes to more accurate operation.

### List of Supported Exporters:
* **Mineways** 🟡
* **jmc2obj** 🟢
* **MiEx** 🔴

ℹ️ **Legend:** 🟢 — **Full support**, 🟡 — **Partial support**, 🔴 — **Not supported**.

## 🖥 Supported Operating Systems
Currently, development is done on **Windows 11**. I previously actively used **Linux**, so MiBlend maintains compatibility established back then where possible.
On **macOS**, the situation remains uncertain: as it's a Unix-like system, theoretically everything **should work**, but comprehensive testing on this platform has not been conducted.

### List of OS:
* **Windows** 🟢
* **Linux** 🟡
* **macOS** ❓

ℹ️ **Legend:** 🟢 — **Full support**, 🟡 — **Possible issues**, ❓ — **Compatibility unknown** (functionality depends on the specific case).
